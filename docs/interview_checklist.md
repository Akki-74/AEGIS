## 1. The Core Interview Questions & Model Answers

### Q1: "How do you distinguish legitimate administrator PowerShell from malicious attacker PowerShell?"
> **Weak Answer:** *"I look for suspicious keywords like `Invoke-Mimikatz` or base64 encoded commands in PowerShell logs."*  
> (Why it fails: Admins use base64 in deployment scripts, and attackers trivially obfuscate or rename functions.)
>
> **AEGIS Senior Answer:**  
> *"In AEGIS, we treat atomic PowerShell script-block events (Event 4104) as **low-to-medium fidelity building blocks rather than standalone critical alerts**. Instead of relying on a single indicator:
> 1. We inspect behavioral combos: Does PowerShell spawn from an unusual parent (e.g. `wmiprvse.exe` or `winword.exe` rather than `explorer.exe`)? Does it initiate an outbound network connection (Sysmon Event 3) to an unclassified IP within 120 seconds?
> 2. More importantly, we use **entity-graph correlation**: An admin executing `Get-Service` or `Install-Module` generates a low-weight cluster restricted to that workstation. Conversely, if a PowerShell session shares a Process GUID lineage with an LSASS memory access handle (Event 10 with mask `0x1010`), and that same Logon ID initiates a Type 3 network logon to a Domain Controller on port 445, AEGIS links these across the process and session graph. The multi-factor scoring engine boosts the score from 0.18 to 0.75+ because it satisfies multiple kill-chain phases (Execution + Credential Access + Lateral Movement). This contextual clustering eliminates the admin false positive without loosening detection sensitivity."*

### Q2: "What are the limitations of Sysmon for PPID spoofing detection?"
> **Senior Answer:**  
> *"Sysmon Event 1 populates the `ParentImage` and `ParentProcessGuid` fields based on the information passed in the process attributes. When an adversary uses `CreateProcess` with `PROC_THREAD_ATTRIBUTE_PARENT_PROCESS`, Windows allows a process to explicitly specify a fake parent (e.g., pointing to `explorer.exe` or `services.exe`).
>
> In Sysmon, this means Event 1 records the **claimed parent**, not the real creator process. In AEGIS:
> 1. We detect anomalies by identifying **impossible parent-child pairings** (e.g., `services.exe` spawning an interactive `cmd.exe` or `powershell.exe`, or `explorer.exe` spawning protected subsystem processes like `lsass.exe` or `csrss.exe`).
> 2. We compare the parent's `ProcessCreateTime` with the child's `ProcessCreateTime`—if the claimed parent started after the child, spoofing is confirmed.
> 3. We explicitly acknowledge this as a telemetry limitation and document that closing this gap requires **Kernel ETW** (`Microsoft-Windows-Kernel-Process`) or an EDR kernel callback (`PsSetCreateProcessNotifyRoutineEx`), which records the actual creator PID."*

### Q3: "Explain how you handle Logon ID and Process GUID stitching across multiple hosts."
> **Senior Answer:**  
> *"A frequent bug in naive correlation engines is treating Windows Logon IDs or Sysmon Process GUIDs as globally unique:
> - **Logon IDs (LUIDs)** are locally generated 64-bit integers (`0x3E7`, `0x1A2B3C`) that reset upon reboot and are only unique within a single operating system instance. If you correlate alerts solely on `logon_id="0x3E7"` across an enterprise, you will merge the local `SYSTEM` account actions of 500 different computers into one giant fictitious incident.
> - **Process GUIDs** generated by Sysmon incorporate boot time and sequence numbers, which can repeat across reboots or virtual machine snapshots.
>
> In AEGIS, we solve this in the `EntityResolver` by creating **globally unique composite keys**:
> - Process Entity ID: `"{hostname}|{process_guid}"`
> - Logon Session Entity ID: `"{hostname}|{logon_id}"`
> - User Canonicalization: Both Downlevel (`CORP\jdoe`) and UPN (`jdoe@corp.local`) formats are normalized to lowercase `corp\jdoe`. Computer accounts ending with `$` are tagged with `is_machine_account=True` so they never conflate with human interactive credentials."*

### Q4: "How do you evaluate False Positive rates without a massive production SIEM?"
> **Senior Answer:**  
> *"We follow a defensible, pre-registered testing methodology:
> 1. **Baseline Corpus:** We record several days of benign administrative telemetry from test workstations and servers running routine workloads: software installations, remote PowerShell scripts, GPO updates, Defender background scans, and daily file share access.
> 2. **Metric Definition:** We calculate **alerts per host-day**:
>    $$\text{FP Rate} = \frac{\text{Alerts on Benign Data}}{\text{Monitored Hosts} \times \text{Duration in Days}}$$
> 3. **Tuning Loop:** Every time an exclusion is added (e.g., excluding `WerFault.exe` from LSASS handle rules), we require that exclusions be constrained by **full path and signer**, never file name alone. We measure the delta in alerts per host-day and maintain a tuning changelog in `aegis.eval.false_positives`."*

## 2. Telemetry Quick Reference Cheat Sheet

| Event Source | ID | What It Proves | Critical Fields to Inspect |
|--------------|----|----------------|----------------------------|
| **Sysmon** | 1 | Process spawned | `Image`, `CommandLine`, `ParentImage`, `ProcessGuid`, `ParentProcessGuid`, `User` |
| **Sysmon** | 3 | Network connection | `SourceIp`, `DestinationIp`, `DestinationPort`, `Image` |
| **Sysmon** | 8 | Remote thread created | `SourceImage`, `TargetImage`, `StartAddress` |
| **Sysmon** | 10 | Process opened (handle) | `SourceImage`, `TargetImage`, `GrantedAccess` (`0x1010`, `0x1410`, `0x1FFFFF`) |
| **Sysmon** | 25 | Tampering / Hollowing | `Image`, `Type` (`Image is replaced`, `Process hollowing detected`) |
| **Security** | 4624 | Logon succeeded | `LogonType` (Type 3 = Network, Type 10 = RDP), `TargetUserName`, `IpAddress` |
| **Security** | 4768 | Kerberos TGT (AS-REQ) | `PreAuthType` (0 = AS-REP Roasting candidate), `TargetUserName` |
| **Security** | 4769 | Kerberos TGS Ticket | `TicketEncryptionType` (`0x17` = RC4/Kerberoasting), `ServiceName` (no `$`) |
| **Security** | 4886/4887 | Certificate Request | `Attributes` (contains `SAN:` or custom UPN/DNS subject alt name) |
| **PowerShell**| 4104 | Full script executed | `ScriptBlockText` (de-obfuscated script text captured pre-execution) |

## 3. How Offensive Knowledge Informs Defensive Engineering in AEGIS

| Offensive Technique | Attacker Optimization | AEGIS Defensive Counter-Optimization |
|---------------------|-----------------------|--------------------------------------|
| **Kerberoasting** | Attacker requests RC4 (`0x17`) tickets because RC4 hashes are vastly faster to crack than AES-256 with hashcat. | Rule filters strictly on `TicketEncryptionType == 0x17` and filters out machine accounts (`ServiceName` ending in `$`), then looks for volume bursts. |
| **Process Injection** | Attacker unhooks `ntdll.dll` or calls direct syscalls to evade userland API monitoring in EDRs. | AEGIS focuses on kernel-level telemetry (`SysmonDrv.sys` Event 10 / Event 8 / Event 25) which catches the resulting kernel handle creation regardless of whether userland hooks were stripped. |
| **Living off the Land** | Attacker renames binaries (`evil.exe` -> `svchost.exe`) or uses LOLBins to blend into trusted image paths. | Rules inspect `OriginalFileName` PE header, unusual command-line flags (`-urlcache`, `-split`, `javascript:`), and parent-child hierarchy rather than file name alone. |
